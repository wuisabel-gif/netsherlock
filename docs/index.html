Why can’t machine A talk to machine B?

NetSherlock investigates the scene. It collects structured evidence, compares observations, and reports only what the facts support — never more.

✓ DNS resolved to 10.0.0.31
✓ Host reachable, 2.4 ms
✗ TCP/5432 connection refused
Verdict: The host is reachable, but nothing accepted TCP/5432. Investigate whether the service is listening, bound elsewhere, or a firewall is rejecting the connection.

Evidence, not speculation

Every check produces a structured result with an explicit status. A timeout, a refusal, a DNS failure, and an unreachable network are different crimes.

DNS

Resolves hostnames through the OS resolver and records every address returned.

netsherlock dns example.com --json

Ping

Checks reachability without assuming a failed probe means the host is down.

netsherlock ping example.com

Port

Tests DNS, reachability, and a TCP port in one command.

netsherlock port example.com 443

Trace

Records the route toward the destination with a bounded timeout.

netsherlock trace example.com

Inspect

Runs multiple local checks from a generic JSON or YAML configuration.

netsherlock inspect network.yml

Structured output

Every result can be emitted as JSON for scripts, dashboards, and further analysis.

netsherlock port example.com 443 --json | jq .

The method

  1. Measurement

    Run the smallest useful check: resolve a name, open a socket, trace a route.

  2. Evidence

    Record what happened as a structured Result object with a precise status.

  3. Diagnosis

    Compare related results. Separate observed facts from possible explanations.

  4. Presentation

    Render human-readable findings that state only what the evidence proves.

Field notes

Read-only by default

NetSherlock never changes routes, firewalls, services, DNS configuration, or passwords unless a future command explicitly asks for confirmation.

Deterministic tests

Tests use localhost, temporary TCP servers, injected resolvers, and fixtures. They do not require public Internet hosts.

Exit codes

0 = success, 1 = observed network/service failure, 2 = invalid input/configuration, 3 = internal error.

NetSherlock is an independent, general-purpose project. No course material, testbed scripts, or assignment code is used.
